# The package index this page ships

`package_index.json` is generated by `scripts/make-avr-index.py`. It describes
one platform, `arduino:avr@1.8.6`, whose archive is the real Arduino AVR core
source tarball from `github.com/arduino/ArduinoCore-avr` tag `1.8.6`, repacked
so the installer accepts it.

The tool entries — `avr-gcc`, `avrdude`, `arduinoOTA`, `ctags` — are **dummy
archives**. They contain small text files named like the real binaries. The
installer verifies their SHA-256 and unpacks them, and then nothing in this page
ever runs them: `web/avr-driver.js` answers every tool invocation itself from the
wasm toolchain in `web/tools/avr/`. They exist so that the installer finds the
tools its index says the platform needs.

The consequence, stated plainly: a compile works, and an **upload does not**.
Uploading needs avrdude talking to a serial port, and the page has no avrdude.

The archive URLs are absolute and point at `https://arduino-wasm.invalid/indexes/avr/`.
That host does not exist. `arduino-cli` uses the URL from the index verbatim, so
the page installs a `fetch` shim that maps that origin onto its own directory
(`web/page-avr.js`, `createIndexFetch`). Regenerating the index with a different
`--base-url` means changing `AVR_ORIGIN` to match.

To rebuild both this index and its archive:

```
python3 scripts/make-avr-index.py --out web/indexes/avr \
  --base-url https://arduino-wasm.invalid/indexes/avr/
```

The core archive is downloaded from GitHub by that script. It is committed here
so that the page and `test/avr.mjs` install from the same bytes without a
network.
