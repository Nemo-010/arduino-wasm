# The nRF52 index this page carries

`nrf52_index.json` is generated by `scripts/make-nrf52-index.py`. It describes
one platform — `Seeeduino:nrf52@1.1.9`, the Seeed nRF52 Boards core, which
covers the XIAO nRF52840 — plus the three tool packages that platform declares.

Three of the four payloads here are real bytes:

- `Seeed_nRF52_Boards-1.1.9.tar.bz2` is the vendor's own archive, shipped whole
  and byte-identical to the one `files.seeedstudio.com` publishes
  (`sha256 2c22069b…e6f3`, 23,218,120 bytes). The core sources, the link
  script, the softdevice API headers and the board definitions all come out of
  it.
- `tools/CMSIS-5.7.0.tar.gz` is a **subset** of the vendor's 26 MB CMSIS
  archive: `CMSIS/Core/Include/`, `CMSIS/DSP/Include/` and
  `CMSIS/DSP/Lib/GCC/libarm_cortexM4lf_math.a`. That archive is not executed —
  it is read by the compiler's include path and by `ld` — so it has to be the
  real thing.
- `tools/arm-none-eabi-gcc-9-2019q4.tar.gz` and `tools/nrfjprog-9.4.0.tar.gz`
  are **stand-ins**: 299 and 182 byte archives holding one small text file each,
  named like the binaries the platform expects. The installer verifies their
  SHA-256 and unpacks them, and nothing in this page ever runs them — the
  compiler in this page is arm-none-eabi GCC built to wasm, and it answers
  through the exec seam (`web/arm-driver.js`), not through
  `packages/Seeeduino/tools/arm-none-eabi-gcc/`.

The consequence, stated plainly: a compile works, and an **upload does not**.
`recipe.objcopy.zip.pattern` runs `adafruit-nrfutil`, which is a Python program;
this page ports the `dfu genpkg` subcommand to JavaScript (`web/nrfutil.js`) and
produces a byte-identical package, but actually flashing needs
`adafruit-nrfutil dfu serial` over WebSerial, and that is not wired up.

The archive URLs are absolute and point at
`https://arduino-wasm.invalid/indexes/nrf52/`. That host does not exist.
`arduino-cli` uses the URL from the index verbatim, so the page installs a
`fetch` shim that maps that origin onto its own directory
(`web/page-index.js`, `createIndexFetch`). Regenerating the index with a
different `--base-url` means changing `PAGE_ORIGIN` or `NRF52_BASE` to match.

## Why this file is not called `package_index.json`

`arduino-cli` saves each package index under the **basename** of its URL
(`internal/arduino/resources/index.go`, `IndexFileName`). The AVR index this
page also ships is `indexes/avr/package_index.json`, so an index here called
`package_index.json` would be written to the same file in the CLI's data
directory and would overwrite the AVR one. The AVR platform then disappears with
`Platform 'arduino:avr' not found: package arduino not found` — measured, and
`test/page-compile.mjs` fails exactly there if the two names ever collide again.

## Rebuilding

```
python3 scripts/make-nrf52-index.py --out web/indexes/nrf52 \
  --base-url https://arduino-wasm.invalid/indexes/nrf52/
```

The script downloads the vendor index on every run and takes the platform's
metadata from it, so the board list here cannot drift from Seeed's. The vendor
index itself is not pinned — it moves when Seeed publishes — but the platform
archive and the CMSIS archive are pinned by SHA-256 **and** by the size the
index declares, and a mismatch stops the run.
